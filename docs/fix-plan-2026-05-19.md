# 修复计划

- 计划日期: 2026-05-19
- 对应审查报告: `docs/code-audit-2026-05-19.md`
- 目标: 先修安全与正确性，再补齐未完成功能，最后做仓库卫生和性能优化

## 第一阶段: 立即修复（P0）

### 1. 后台 RBAC 真正落地

- 目标:
  - `superadmin` 与 `operator` 的读写边界清晰可控。
  - 敏感能力默认只给 `superadmin`。
- 处理项:
  - 在 `internal/router/router.go` 为管理员管理、密码重置、权限发放、审计日志、反馈状态更新等路由挂上 `RoleMiddleware(...)`
  - 明确各资源的角色矩阵并写入文档
  - 在 `frontend/src/router/index.js` 与 `frontend/src/layouts/BasicLayout.vue` 增加按角色过滤的路由/菜单显示
- 验证:
  - 新增后端授权测试: `operator` 对敏感接口返回 `403`
  - 管理端用两个角色账号做联调

### 2. 被禁用账号即时失效

- 目标:
  - 用户或管理员状态变更后，不再允许旧 token 继续访问
- 处理项:
  - 在 `MiniProgramAuth` / `AdminAuth` 中回表校验账号是否存在且 `status=1`
  - 对被禁用账号直接返回 `401/403`
  - 评估是否在禁用动作时顺带拉黑当前 token
- 验证:
  - 登录后禁用账号，再访问任意受保护接口应立即失败

## 第二阶段: 高优先级修复（P1）

### 3. 让管理员题库权限真正参与授权

- 目标:
  - `admin_bank_permissions` 从“记录表”变成“有效授权来源”
- 处理项:
  - 在题库列表、题目列表、题目导入/编辑/删除、题库编辑/删除中接入权限校验
  - 为 `superadmin` 保留全量访问，为 `operator` 限制到已授权题库
  - 统一封装 `CanAdminAccessBank(adminID, bankID)` 之类的服务方法
- 验证:
  - 未授权 operator 无法看到或修改非授权题库
  - 授权/撤权后行为立即变化

### 4. 修正小程序环境配置

- 目标:
  - 区分开发/测试/生产环境，不再硬编码 `localhost`
- 处理项:
  - 为小程序请求层抽出环境配置文件
  - 支持至少 `dev` / `prod` 两套 API base URL
  - 补充 README 或部署文档中的配置说明
- 验证:
  - 本地与生产地址可独立切换

### 5. 修正审计日志前后端契约

- 目标:
  - 列展示、搜索、日期筛选全部可用
- 处理项:
  - 统一字段命名，选一套: `target/target_id` 或 `resource/resource_id`
  - 统一筛选参数命名，前后端保持一致
  - 补全 action/resource 枚举显示
- 验证:
  - 日期筛选、操作人筛选、资源列展示均正确

### 6. 修复小程序考试记录分页

- 目标:
  - 页码参数真实传到后端，滚动加载不重复第一页
- 处理项:
  - 把 `getExamRecords` 改为直接传 `{ page, page_size }`
  - 顺手检查其余小程序 GET API 是否有同类 axios/`wx.request` 混用问题
- 验证:
  - 至少构造 2 页数据，确认分页游标正常推进

## 第三阶段: 中优先级修复（P2）

### 7. 给授权关系补唯一约束与幂等写入

- 目标:
  - 同一个用户/管理员对同一题库不会重复授权
- 处理项:
  - 为 `user_bank_access(user_id, bank_id)` 增加联合唯一索引
  - 为 `admin_bank_permissions(admin_id, bank_id)` 增加联合唯一索引
  - 仓储层改为幂等写入或重复时返回明确错误
  - 清洗历史重复数据
- 验证:
  - 重复授权不会新增重复行
  - 统计数字不再因脏数据膨胀

### 8. 完成或下线题库统计独立页

- 目标:
  - 避免仓库里存在“页面有代码但用户永远进不去”的半成品
- 处理项:
  - 二选一:
    - 接入路由和菜单，并补齐后端 `top_wrong_questions`
    - 或删掉独立页，只保留题库管理里的统计抽屉
- 验证:
  - 页面路径可访问，或代码已被彻底移除

### 9. 修复 `UpdateAdminUser` 的部分更新语义

- 目标:
  - 未提交的字段不应被误写为空值
- 处理项:
  - Handler 侧区分“未传字段”和“显式传空”
  - Repository 侧只更新实际变更字段
- 验证:
  - 仅更新昵称/状态时，角色保持不变

## 第四阶段: 收尾治理（P3）

### 10. 清理仓库草稿文件与忽略规则

- 目标:
  - 减少误提交与误阅读
- 处理项:
  - 删除 `internal/handler/handler.go.my-edits`
  - 将 `*.my-edits`、本地审查草稿、构建输出等补充进 `.gitignore`
- 验证:
